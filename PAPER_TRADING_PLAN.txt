PHASE 1: Fix Research Gates (Get to ROBUST_OOS)
-----------------------------------------------------------------

Before paper trading is even conceivable, the strategy must pass all
automated research gates. Currently it fails 4:

1. cost_stress_survives
   - Strategy cannot survive 10 bps fee stress.
   - Cost drag is 11.90% on a gross Sharpe of only 0.1572.
   - Need to reduce turnover, increase signal strength, or both.

2. delay_stress_survives
   - Strategy cannot survive execution delay.
   - Signal degrades too quickly with latency.

3. bootstrap_positive_prob
   - Only ~56.6% probability that Sharpe > 0.
   - Needs to exceed the configured threshold (typically 80-90%).

4. placebo_separates
   - Placebo percentile at 0.45.
   - Needs to be higher (typically 0.90+, meaning the real strategy
     beats 90% of null runs).
   - Adjusted p-value of 0.571 means no statistical separation from
     noise.

Actions needed:
- Improve the underlying signal (currently weak/noisy).
- Reduce turnover to lower cost drag.
- Re-run the full pipeline after improvements.
- Verify all 4 gates pass on fresh OOS evidence.
- Achieve ROBUST_OOS promotion state.

-----------------------------------------------------------------
PHASE 4: Wire Safeguards into the Order Flow
-----------------------------------------------------------------

Currently Safeguards is a standalone class that nobody calls.
The PaperBroker.submit() method must:

1. Check safeguards.check_position(intended) — reject if over limit.
2. Check safeguards.check_daily_loss(daily_return) — trip kill switch
   if breached.
3. Check safeguards.check_drawdown(current_drawdown) — trip kill switch
   if breached.
4. Check safeguards.check_data_freshness(last_bar_ts, now) — reject if
   data stale.
5. Only proceed with fill if ALL safeguards pass.
6. If kill switch is active, reject all new orders until manually
   reset.


-----------------------------------------------------------------
PHASE 5: Build the Paper Validation Framework
-----------------------------------------------------------------

The promotion state machine has:
PAPER_READY -> PAPER_VALIDATED -> LIVE_ELIGIBLE

The code explicitly states these are "deliberately not automatable here."
You need to define:

| State           | Entry Criteria                                                |
|-----------------|---------------------------------------------------------------|
| PAPER_READY     | All research gates pass + paper broker hardened + safeguards  |
|                 | wired                                                         |
| PAPER_VALIDATED | Minimum N days of continuous paper execution with: no         |
|                 | safeguard breaches, position reconciliation holds, P&L        |
|                 | attribution matches, kill switch tested                       |
| LIVE_ELIGIBLE   | Extended paper validation (typically 1-3 months) +            |
|                 | operational readiness review                                  |

Build:
- A paper-validation runner that executes the strategy against
  live/delayed market data.
- A paper-validation report that feeds evidence back into the
  promotion gate.
- Integration with the registry/leaderboard so paper evidence is
  recorded alongside research evidence.
