PHASE 3 — BUILD A PROPER WALK-FORWARD TESTING FRAMEWORK
Do NOT optimize on the full historical dataset.

Use rolling or expanding windows:

Train → Validation → Test
then roll forward.

Example:

Validation: 2022
Test: 2023
then roll forward.

The exact dates should depend on the dataset.

For every strategy, preserve:

- test period

- features selected
- number of trials
- final untouched OOS result

PHASE 4 — ROBUSTNESS / ANTI-OVERFITTING TESTS
Every promising strategy should pass several checks:

1. Parameter perturbation
   Test nearby parameter values.

2. Transaction-cost stress
   Increase commissions/fees.

3. Slippage stress
   Test worse execution assumptions.

4. Signal-delay test
   Delay the signal by one or more bars.

5. Missing-data test
   Remove or corrupt portions of input data.

6. Regime test
   Test separately in:
   - bull markets
   - bear markets
   - high volatility
   - low volatility
   - high inflation/rate environments where relevant

7. Cross-asset test
   Determine whether the effect survives outside the original instruments.

8. Placebo / randomized feature test
   Replace a feature with noise or shuffled values.
   A real edge should deteriorate.

9. Bootstrap / resampling
   Estimate uncertainty around returns and risk statistics.

10. Multiple-hypothesis correction
    Account for the number of strategies/features tried.

11. Backtest-overfitting diagnostics
    Measure how likely the observed best result is a search artifact.

12. Deflated/performance-adjusted statistics where appropriate.

PHASE 5 — STRATEGY DISCOVERY ENGINE
Create a controlled strategy search system.

Search combinations of:
technical features
× fundamental features
× macro regime
× information features
× entry rules
× exit rules
× position-sizing rules
× risk rules

BUT:
The discovery engine must enforce:
- no look-ahead
- no survivorship bias
- no future universe selection
- no data leakage between folds
- bounded parameter ranges
- trial counting
- reproducible random seeds
- out-of-sample evaluation
- rejection of fragile strategies

Do not select the strategy with the highest in-sample Sharpe.
Select based on robust OOS performance.

PHASE 13 — PAPER TRADING
Do NOT move directly from backtest to real money.

- monitor feature drift

Run this long enough to establish that live behavior resembles research assumptions.

IMPORTANT
A strategy that looks excellent in backtests is not automatically tradable.
The goal is not the highest backtest return.
The goal is a robust, reproducible, economically plausible edge that survives
out-of-sample testing, costs, regime changes, and live execution.
