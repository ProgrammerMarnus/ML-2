PHASE 1 — REAL POINT-IN-TIME DATASET
1. Start with one market/universe: SPY initially.
2. Define the historical period and timeframe explicitly.
3. Obtain clean OHLCV data.
4. Preserve raw downloaded data before transformation.
5. Version the dataset.
6. Standardize timestamps and timezone handling.
7. Define exactly when each bar becomes available to the strategy.
8. Build automated data-quality checks for:
   - missing bars
   - duplicate timestamps
   - invalid OHLC relationships
   - volume anomalies
   - timestamp ordering
   - timezone consistency
   - corporate-action handling where relevant
9. Never use revised/future information.

REQUIRED RAW/PIT FIELDS
- symbol
- event_time
- publication_time where applicable
- source
- raw_value
- processed_value
- availability_time

CRITICAL RULE
A feature may only be used after the information was actually available to the strategy.

PHASE 2 — POINT-IN-TIME FEATURE ENGINE
Build one standardized feature table.

INITIAL FEATURE SET
- returns/momentum
- trend
- moving-average relationships
- mean reversion
- volatility
- volume/liquidity
- market breadth where available
- regime variables

For every feature record:
- definition
- source
- timestamp rule
- availability rule
- missing-data behavior
- look-ahead test
- normalization/scaling rule

All transformations must be fitted only on information available in the corresponding training window.

PHASE 3 — BASELINE MODEL
Create a deliberately simple baseline before any information-layer features.

Baseline sequence:
price/volume
→ point-in-time features
→ simple model
→ signal
→ position sizing
→ transaction costs/slippage
→ walk-forward OOS evaluation

Run at least:
- logistic regression
- one tree-based model

Do not select a model because it has the highest in-sample Sharpe.

PHASE 4 — TRUE WALK-FORWARD FRAMEWORK
Use rolling or expanding windows:
Train → Validation → Test → roll forward.

For every fold save:
- train start/end
- validation start/end
- test start/end
- purge/embargo gap
- features used
- parameters selected
- model version
- number of trials
- OOS predictions
- OOS returns

The final OOS test must remain untouched until the research specification is frozen.

No full-history optimization.
No test-period tuning.
No feature selection using future folds.
No information leakage across folds.

PHASE 5 — BASELINE DIAGNOSTICS
For the clean real-data baseline calculate:
- OOS Sharpe
- CAGR
- max drawdown
- Calmar
- Sortino
- hit rate
- turnover
- trade count
- transaction costs
- slippage
- tail loss
- AUC where applicable

- beta/market exposure
- volatility

Also compare against:
- buy and hold benchmark
- cash/zero-return benchmark where useful
- simple naïve signal benchmark

PHASE 6 — ANTI-OVERFITTING / ROBUSTNESS GATES
Every promising strategy must pass:

1. Parameter perturbation
   Test nearby parameter values.

2. Transaction-cost stress
   Test progressively higher costs.

3. Slippage stress
   Test worse execution.

4. Signal-delay stress
   Test one or more bars of delay.

5. Missing-data stress
   Remove/corrupt selected inputs.

6. Regime analysis
   Separate bull, bear, high-volatility, and low-volatility periods.

7. Cross-asset validation
   Only after the SPY baseline is stable.

8. Placebo/randomized-feature tests
   Shuffle/replace features and verify that the real strategy performs materially better than the null.

9. Bootstrap/resampling
   Estimate uncertainty around returns and risk statistics.

10. Multiple-hypothesis correction
    Account for the number of strategies/features tried.

11. Backtest-overfitting diagnostics
    Measure the probability that the best result is a search artifact.

12. Deflated/performance-adjusted statistics where appropriate.

PROMOTION RULE
A strategy should not be promoted merely because its raw OOS Sharpe is positive.
It must survive costs, delay, perturbation, placebo testing, and uncertainty checks.

PHASE 7 — INVESTIGATE THE CURRENT AUC / PLACEBO PROBLEM
The first V2 validation showed that low predictive AUC and placebo results can coexist with apparently positive backtest statistics.

Therefore explicitly test whether return improvements arise from:
- genuine directional information
- threshold effects
- volatility timing
- market exposure
- regime selection
- path dependence
- accidental optimization/search noise

Required diagnostics:
- prediction distribution
- long/short or exposure distribution
- return attribution by signal bucket
- return attribution by volatility bucket
- return attribution by market regime
- feature permutation importance
- placebo/null distribution
- benchmark-relative performance

Only after a strategy passes the research gates.

Paper-trading system must:

Do not move directly from backtest to real capital.

PHASE 15 — LIVE DEPLOYMENT
Only after successful paper trading.

GO / NO-GO CRITERIA
A strategy is eligible for paper trading only if all of the following are satisfied:
- data-quality checks pass
- point-in-time checks pass
- no known leakage exists
- OOS evaluation is genuinely untouched
- transaction-cost stress is acceptable
- slippage stress is acceptable
- signal-delay stress is acceptable
- placebo performance is materially weaker than real performance
- uncertainty is acceptable
- performance is not isolated to one narrow regime
- implementation is reproducible
- experiment is fully registered

A strategy is NOT eligible merely because:
- in-sample Sharpe is high
- one walk-forward result is high
- the backtest return is high
- a complex model beats a simple model
- social/news features improve one experiment
